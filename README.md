# 내비게이션 앱 · ARM64

수정된 티맵과 네이버지도를 ARM64 기기용으로 패키징한 저장소입니다.

| 앱 | 버전 | ARM64 APK | 저장소 압축 파일 |
|---|---|---:|---:|
| 티맵 | 11.8.2.4051 | 208.7MB | ZIP 97.8MB · 1개 |
| 네이버지도 | 6.11.2.2 | 234.8MB | ZIP 158.0MB · 2개로 분할 |

MB는 1,000,000바이트 기준입니다. GitHub 일반 Git 파일 제한은 100MiB(104,857,600바이트)이므로 티맵 ZIP은 하나로, 네이버 ZIP은 80MiB 단위의 두 파일로 보관합니다.

## 검색·안내 앱 전환·신호 표시

- 홈·돋보기·아리아의 네이버 검색은 원문으로 조회한 뒤 정확한 결과가 없으면 한글 사이의 띄어쓰기를 합쳐 한 번 더 조회합니다. 원래 입력과 네이버 장소명 표시는 유지합니다. `캠퍼스`와 `캠퍼스학원`은 같은 이름으로 판별하되, `검단`과 `신검단` 같은 지점명은 구분합니다.
- 티맵 홈 검색뿐 아니라 주행·안심주행 화면의 **오른쪽 아래 돋보기 → 검색 결과**에서도 네이버 장소 검색 버튼을 제공합니다. 입력한 검색어를 그대로 이어서 조회합니다.
- 아리아가 말한 지점과 다른 유사 지점을 추천하면, 원래 발화로 네이버도 조회합니다. 티맵 후보에 정확한 지점이 없고 네이버에 정확히 일치하는 지점이 있으면 우선 추천하며, 기존 목록 아래의 네이버 버튼에 장소명을 표시합니다. 이 상태에서 “그래”라고 확인하면 해당 좌표로 경로를 조회합니다. 자동 팝업은 열지 않으며, 사용자가 버튼을 눌렀을 때만 네이버 결과를 보여줍니다. 지점명은 유지하며, Naver 장소 ID를 티맵 POI ID로 사용하지 않습니다.
- 아리아가 음성 인식을 완료하면 검색어를 저장해 홈, 경로 안내, 안심주행의 네이버 검색 버튼에 전달합니다.
- 양쪽 앱은 병합 로직이 채택한 가까운 방지턱을 각 앱의 순정 아이콘으로 표시합니다. 티맵 지도에서 순정 안전 안내가 이미 표시 중이면 그 안내를 우선합니다.
- 티맵은 수신 즉시 보조 신호를 갱신합니다. 상세 방향 정보가 없는 경우 기본 신호에 포함된 방향과 상태를 표시합니다.
- 아리아 화면에서 네이버 장소를 선택하면 검색창을 닫고 선택한 장소를 기억합니다. 이어서 “그래”라고 확인하면 선택한 좌표로 경로를 조회합니다. 새로운 장소를 말하거나 취소하면 이전 선택을 해제합니다.
- 네이버 화면의 겹침 확인은 UI 라벨만 읽으며, Compose 동작 객체를 문자열로 변환해 발생하던 종료 오류를 수정했습니다.
- 두 앱이 같은 목적지로 안내 중일 때 전환할 앱의 아이콘이 표시된 원형 버튼으로 화면·음성·안내 주체를 바꿉니다. 두 앱의 기존 경로를 다시 만들지 않습니다. 앱별 경로가 다르면 전환한 앱의 경로를 따릅니다.
- 앱 전환 버튼은 Android 14 이상에서 지원합니다. 상대 앱의 응답·주행 상태·같은 주행 세션을 확인하고, OS가 전달한 발신 앱과 APK 서명을 검증합니다. 상대 앱이 응답하지 않으면 현재 안내를 유지합니다. 종료된 앱의 경로를 자동 복구하는 기능은 포함하지 않습니다.
- 다른 앱이나 홈 화면으로 나가면 선택한 내비의 작은 안내창만 사용하고, 반대편 내비의 음성과 작은 안내창은 억제합니다.
- 신호는 수신된 방향의 화살표·색·시간을 각각 표시합니다. 수신되지 않은 방향이나 다음 신호 주기는 추정하지 않습니다. 티맵 순정 신호 시간의 1~5초 표시는 숨기며, 추가 방향별 패널은 별도로 표시합니다.
- 신호 보조 패널은 순정 신호 아래를 우선 사용합니다. 티맵은 왼쪽을 맞추고, 네이버지도는 오른쪽으로 조금 옮깁니다. 네이버의 순정 현재 속도와 안전운전 표지판 묶음은 보조 패널만큼 내려가고, 보조 신호가 사라지면 원래 높이로 돌아옵니다. 두 앱 모두 방향 화살표와 남은 시간을 해당 신호색으로 표시합니다. 전환 버튼은 기존 조작 버튼의 세로 중심에 맞춥니다. 속도·표지판·차선·기존 신호등을 가리지 않도록 위치를 찾습니다. 키보드와 검색 화면에서는 전환 버튼을 숨깁니다.
- 두 앱은 서로의 응답 상태를 감시합니다. 앱 연결 끊김과 위치 갱신 지연을 구분해 기록하며, 지도 위 알림은 약 5초 후 사라집니다. ×로 즉시 닫을 수 있고, 같은 끊김은 반복해서 알리지 않습니다. 끊김만으로 안내 앱을 자동 전환하지 않습니다.
- C4에서 양쪽 앱의 신호를 사용하려면 수신부 변경도 필요합니다. 해당 openpilot 변경 커밋은 수신부 `180f3ae`, 경로 방향 한 개의 큰 신호 타이머 `d625960`, NAV 옆 원형 N/T 소스 배지 `34e9756`입니다. 경로·TBT는 선택한 앱을 유지하고, 유효한 신호는 백그라운드 앱에서도 받습니다.

## APK 복원

1. 이 저장소를 Git으로 받거나 GitHub의 **Code → Download ZIP**으로 받아 압축을 풉니다.
2. `packages` 폴더와 파일 이름을 그대로 유지합니다.
3. **`restore-apks.cmd`를 실행**합니다.
4. 생성된 `dist` 폴더의 APK를 폰으로 옮겨 설치합니다.

- `dist/tmap-c4-arm64.apk`
- `dist/naver-map-c4-arm64.apk`

티맵은 `packages/tmap-c4-arm64.zip`을 일반 압축 해제로 풀어도 됩니다. 네이버지도는 `.part001`과 `.part002`가 모두 있어야 하며, 복원 스크립트가 자동으로 합칩니다. 분할 파일 자체는 설치용 APK가 아닙니다.

복원은 Windows 기본 PowerShell과 .NET으로 실행되며 별도 압축 프로그램이나 Python이 필요하지 않습니다. 각 파일, 합친 ZIP, 복원된 APK의 SHA256과 길이를 `manifest.json`과 대조합니다. 이미 정상 복원된 APK는 다시 덮어쓰지 않습니다.

명령줄에서 앱 하나만 복원하거나 검사할 수도 있습니다.

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\restore-apks.ps1 -App tmap
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\restore-apks.ps1 -App naver-map
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\restore-apks.ps1 -VerifyOnly
```

## 앱에서 GitHub 업데이트

현재 수정본은 **2026.11.19.4 / 빌드 2026111904**입니다. **2026.11.16.1**부터 티맵과 네이버지도 모두 이 저장소의 `main/manifest.json`을 확인합니다. 이 기능이 없는 예전 설치본은 이번 APK를 한 번 직접 설치해야 합니다.

- 앱을 화면에 열면 새 버전을 확인하며, 최근 확인 후 15분 이내에는 반복 조회하지 않습니다.
- 종량제가 아닌 연결에서는 자동 다운로드하고, 그 외에는 다운로드 여부를 묻습니다.
- 네이버지도의 분할 ZIP도 자동으로 합쳐 복원합니다. 파일 크기·SHA256·앱 패키지·설치본과 동일한 서명을 확인합니다.
- 다운로드·서명 검증 후 APK를 **다운로드 폴더**에 저장합니다. 파일명은 `kisa-tmap-빌드번호.apk`, `kisa-naver-map-빌드번호.apk`입니다.
- 완료 알림을 누르면 다운로드 목록이 열립니다. **내 파일 → 다운로드에서 APK를 직접 눌러 설치**합니다. 앱이 설치 화면을 자동으로 열거나 설치 권한 설정으로 이동하지 않습니다.
- 알림을 허용하지 않은 경우에도 파일은 다운로드 폴더에 남으며, 앱에서 저장 완료 메시지를 표시합니다. Android 10 이상에서 별도 파일 접근 권한 없이 저장합니다.
- 삼성 보안 검사는 그대로 적용됩니다. 다운로드 폴더로 저장한다고 의심 앱 경고가 해제되는 것은 아닙니다.
- 이동 중으로 확인된 경우 업데이트 창을 미룹니다. 실제 주행 중에는 업데이트를 설치하지 마세요.

### 다음 수정본 게시

**APK만 GitHub에 추가하면 업데이트되지 않습니다.** 새 빌드 번호, 배포 파일, `manifest.json`을 한 커밋으로 게시해야 합니다.

1. 두 APK에 포함되는 `NaviUpdater.BUILD`를 더 큰 번호로, `VERSION`을 수정 버전으로 올려 다시 빌드·서명합니다. 빌드 검증 보고서의 `update_build`도 같은 번호여야 합니다. 서명키는 기존과 동일하게 유지합니다.
2. 검증 보고서를 사용해 아래 도구를 실행합니다. 이 도구가 압축·분할·해시 계산과 업데이트 목록 작성을 수행합니다.
3. `restore-apks.ps1`로 복원 검사를 하고, `packages`, `manifest.json`과 변경한 문서를 함께 커밋하여 `main`에 푸시합니다.
4. 폰에서 앱을 다시 열어 업데이트를 내려받고, 다운로드 폴더에서 APK를 직접 열어 설치합니다. **로컬 커밋만 한 상태에서는 폰에 배포되지 않습니다.**

```powershell
py tools/package-updates.py --checks C:/build/checks.json --version 2026.11.19.4 --notes "수정 내용"
powershell.exe -NoProfile -ExecutionPolicy Bypass -File ./restore-apks.ps1
```

`--checks`는 서명·정렬·APK 내용 보존을 검증하는 `build_current.py`의 보고서입니다. 도구는 실제 APK가 보고서의 크기·SHA256과 일치하는지 검사하고, 동일 빌드 번호에 다른 APK를 게시하는 것도 거부합니다. APK 내부 빌드 번호를 도구가 자동 변경하지는 않습니다.

두 앱의 기본 버전 번호와 별도로 **수정본 빌드 번호**로 업데이트를 구분합니다. 향후 원본 앱 버전이 바뀌면 수정 기능과 업데이트 코드를 새 원본에 다시 적용해 빌드해야 합니다.

## 적용 기능 및 수정사항

아래 내용은 **이 저장소에 포함된 현재 APK 기준**입니다. 티맵과 네이버지도 수정본을 함께 설치해야 앱 간 연동 기능을 사용할 수 있습니다.

### 주요 연동 기능

| 기능 | 적용 내용 |
|---|---|
| **안전운전 정보 안내·C4 연동** | 과속카메라·신호위반 카메라·과속방지턱·구간단속의 종류, 제한속도와 남은 거리를 전달 |
| **신호 정보 연동** | 제공되는 방향별 적색·녹색·황색 상태, 잔여 시간과 교차로 거리 전달 |
| **TBT 길 안내 연동** | 현재·다음 회전/분기 안내의 종류와 남은 거리를 전달 |
| **도로·차선 정보 연동** | 앱이 제공하는 도로 제한속도·도로명·경로·차선 정보를 C4 호환 형식으로 전달 |
| **두 앱 전환과 백그라운드 안내** | 앞쪽 앱의 음성·길 안내를 사용하고, 뒤쪽 앱의 중복 음성·오버레이·C4 데이터 혼합을 억제 |
| **방지턱 정보 공유** | 티맵에 네이버 방지턱을 보완하고, 네이버 안내에도 실행 중인 티맵 순정 방지턱을 병합 |

안심주행/안전운전과 경로 안내 모두 **엔진이 실제로 제공하는 데이터**를 기준으로 연동합니다. C4 화면 표시 및 감속 판단에는 대응하는 C4 수신 코드와 설정이 사용됩니다.

### 1. 티맵·네이버 추천 경로 비교

- 티맵 경로 조회 화면에 **네이버추천** 카드를 추가했습니다.
- 네이버 서버에서 받은 소요시간·도착예정시각·거리·통행료를 기존 티맵 카드와 비슷한 형식으로 표시합니다.
- **티맵추천과 네이버추천 중 소요시간이 짧은 경로를 기본 선택**하며, 시간이 같으면 네이버추천을 선택합니다.
- 조회를 기다리는 동안 자동 안내 카운트를 멈춰, 비교 전에 티맵추천으로 먼저 출발하는 것을 방지합니다.
- 사용자가 카드를 선택하거나 화면을 조작하면 수동 선택을 우선합니다.
- 모의주행이나 뒤로가기로 경로 조회 화면에 돌아올 때 기존 조회 결과와 선택을 재사용하도록 보완했습니다.
- 네이버 경로 조회 중에는 계산 상태·예상 소요 범위·경과 시간을 표시하고, 지연·실패·시간 초과 시 재시도할 수 있게 했습니다. 응답을 받지 못하면 이용 가능한 티맵 경로를 사용합니다.
- 지도에는 네이버가 제공한 경로 선형과 **구간별 교통정보 색상·대표 도로명**을 미리 표시합니다. 교통정보가 없는 구간의 상태는 임의로 만들지 않습니다.
- 네이버 경로 조회는 목적지·경유지의 **좌표**를 사용합니다. 장소 이름은 표시용으로 전달하고, 선택한 목적지를 임의의 다른 진입점으로 바꾸지 않습니다.
- 통행료 미리보기는 티맵 차량 설정을 바탕으로 네이버 서버가 반환한 금액을 사용합니다. 전기차 할인도 서버 응답에 따르며, 모든 도로에 일괄 할인율을 적용하지 않습니다. 실제 네이버 안내에는 네이버 앱의 내 차 설정이 사용되므로 두 앱의 차량 설정을 맞춰 주세요.

### 2. 선택한 앱이 안내하고, 다른 앱은 백그라운드 유지

| 선택한 추천 | 화면·음성 안내 | 백그라운드 안내 | C4의 주 안내 소스 |
|---|---|---|---|
| 티맵추천 | 티맵 | 네이버지도 | 티맵 |
| 네이버추천 | 네이버지도 | 티맵 | 네이버지도 |

- 안내 시작 시 상대 앱에도 같은 목적지와 경유지를 전달합니다. 앱을 여는 짧은 전환 과정이 있을 수 있습니다.
- 백그라운드 앱의 음성을 억제해 안내가 겹치지 않게 했습니다.
- 백그라운드 앱의 작은 길 안내 오버레이가 앞쪽 앱을 가리지 않도록 했습니다.
- 백그라운드 동반 앱의 데이터에 역할 정보를 붙여 C4가 두 앱의 경로·신호·안전정보를 섞지 않도록 했습니다. 방지턱 병합은 아래의 별도 규칙을 따릅니다.
- 각 앱이 자체 엔진으로 안내·경로 이탈 재탐색을 처리합니다. 같은 목적지라도 두 앱이 선택한 실제 경로와 재탐색 결과는 다를 수 있습니다.
- 네이버의 분기·차선·유도선·톨게이트 안내는 실제 네이버지도 앱이 담당합니다.
- 모의주행에서는 상대 앱을 자동으로 실행하지 않습니다.

### 3. 아리아 음성 목적지와 네이버 검색 연동

- 아리아로 집·회사 안내를 시작하거나, 검색한 장소를 목적지로 확정했을 때도 티맵·네이버 소요시간을 비교합니다.
- 더 빠른 앱으로 안내하며, 시간이 같으면 네이버를 선택합니다. 반대 앱은 위의 백그라운드 방식으로 유지합니다.
- 아리아 후보 목록에 **“원하는 장소가 없나요? 네이버에서 찾기”** 버튼을 추가했습니다.
- 버튼을 누르면 인식한 검색어를 네이버 장소검색으로 이어 줍니다. 잘못 인식한 검색어는 직접 수정할 수 있습니다.
- 추천 목록의 첫 번째 장소를 대신 검색하지 않고, 사용자가 말한 검색어를 유지하도록 했습니다.
- 네이버 결과에서 원하는 장소를 선택·확정하면 좌표로 티맵 경로 조회 화면을 엽니다.
- 이 검색 전환은 후보 화면의 버튼으로 실행합니다. 별도의 네이버 검색 전용 음성 명령은 추가하지 않았습니다.

### 4. 티맵 안의 네이버 장소검색

- 티맵 검색 화면·검색 결과 화면에서 **네이버 장소 검색**을 열 수 있습니다.
- 실제 네이버 검색 결과의 장소명·분류·주소·거리·제공되는 영업 상태를 표시합니다.
- 검색 위치를 **현재 지도 중심 / 내 위치 중심**, 정렬을 **관련도순 / 거리순**으로 선택할 수 있습니다.
- 기본값은 현재 지도 중심·관련도순입니다. 아리아 화면에서 지도 중심이 준비되지 않았고 실제 내 위치가 있으면 내 위치 중심으로 표시해 검색합니다.
- 시스템의 라이트·다크 모드에 맞춰 검색 화면 색상을 바꿉니다.
- 중복·잘못된 좌표를 걸러내고, 검색 변경·닫기 후 늦게 온 응답이 기존 결과를 덮어쓰지 않게 했습니다.

### 5. 주행 패턴 학습과 자동 목적지 제안

- **출발 위치·요일·시간대·이전 실제 주행 목적지**를 함께 고려해 목적지를 제안합니다.
- 평일 출퇴근과 특정 요일 일정 같은 초기 패턴에 실제 완료한 주행을 더해, 출발 시간이 달라지거나 자주 가는 목적지가 늘어나는 상황을 반영합니다.
- 정확히 같은 시각이나 고정된 두 번의 방문을 요구하지 않습니다. 출발 장소가 다르거나 후보가 비슷해 확신하기 어려우면 제안을 생략합니다.
- 주행이력에 대한 통계 기반 학습을 기기 안에서 수행합니다. 모의주행을 실제 방문으로 학습하지 않습니다.
- 홈 화면에 **“[목적지]로 가는 중이세요? / 더 빠른 추천 경로로 자동안내합니다”**를 표시합니다.
- **목적지 제안 카운트는 5초**, 경로 조회 후 **안내 시작 카운트는 10초**입니다. 경로 조회에 걸리는 시간은 별도로 필요합니다.
- 화면 조작으로 자동 진행을 취소할 수 있습니다. 화면을 떠나거나 이미 안내 중일 때도 자동 제안을 중단합니다.
- 같은 출발지·목적지를 짧은 시간 안에 반복 제안하지 않도록 했습니다.
- 현재 설정은 평일 자동 제안이며, 주말에는 제안하지 않습니다.
- 지하주차장처럼 GPS 수신 전에도 마지막으로 확인한 위치를 이용해 목적지를 제안하고, 5초 뒤 기존 경로 조회로 진행합니다. **“마지막 확인 위치 기준”**을 표시합니다.
- 티맵·네이버 예상시간을 비교해 더 빠른 쪽으로 안내하며, 시간이 같으면 네이버를 선택합니다. GPS가 잡힌 뒤 현재 지점에 맞추는 동작은 각 앱의 기본 안내를 사용합니다.
- 마지막 위치는 정확도 60m 이내·최대 72시간인 기록만 사용합니다. 앱에 저장된 위치와 안드로이드의 기존 위치 기록 중 최신 유효 위치를 선택하며, 현재 GPS 좌표를 덮어쓰지 않습니다.
- 사용 가능한 위치가 전혀 없으면 **“GPS 확인 중 · 자동 목적지 대기”**를 표시합니다. 실제 방문 학습에는 계속 최신 실제 위치만 사용합니다.

### 6. 홈 화면 자동 안심주행

- 티맵 홈에서 조작이 없으면 안심주행으로 넘어가는 자동 시작과 남은 초 표시를 추가했습니다.
- 일반 홈 대기는 15초입니다. 목적지 제안의 5초 및 경로 조회 화면의 10초와 별도입니다.
- 자동 목적지 제안을 판단하려고 GPS를 기다리는 동안에는 안심주행으로 먼저 넘어가지 않도록 보완했습니다.
- 네이버지도는 앱 실행 시 첫 하단 탭을 **내비게이션**으로 선택하도록 했습니다. 실행 후에는 다른 탭으로 이동할 수 있습니다.

### 7. 과속방지턱 정보 병합

**티맵에서 네이버 방지턱 사용**

- 네이버지도 앱을 실행하지 않아도 주변 안전정보·도로 타일을 조회해 티맵 순정 방지턱 정보에 보완합니다.
- 위치·진행 방향·도로 선형을 맞춰 **앞쪽 방지턱**을 선택하고 남은 거리를 갱신합니다.
- 같은 지점의 중복을 줄이고, 통과한 방지턱이 다시 선택돼 거리가 커지는 현상을 방지합니다.
- 갈림길·평행 도로 등에서 도로가 불확실하면 후보를 제외합니다. 조회에 실패하면 티맵 순정 정보를 유지합니다.
- 단속카메라와 활성 구간단속 데이터는 보존합니다.

**네이버지도에서 티맵 방지턱 사용**

- 실행 중인 티맵의 실제 순정 방지턱 정보를 같은 폰의 로컬 연결로 받아 네이버 안내 목록에 병합합니다.
- 네이버 경로 또는 현재 진행 방향에 맞는 유효한 정보만 사용하고, 중복·지나간 지점·오래된 정보를 제외합니다.
- 네이버의 원래 안내 목록과 함께 거리·우선순위를 계산해 화면·음성 안내와 C4 전송에 사용합니다.
- 티맵에서 네이버로부터 가져온 방지턱을 다시 네이버에 되돌려 넣지 않도록 출처를 구분합니다.
- 이 방향의 공유에는 **티맵이 안심주행 또는 실제 경로 안내 상태로 실행 중**이어야 합니다.
- 네이버의 과속방지턱 안내 설정을 켜야 합니다. 네이버의 속도별 안내 범위·연속 방지턱 묶음·동시 안내 개수 등 기존 조건도 적용됩니다.

현재 배포본에는 사용자가 좌표 파일로 방지턱을 수동 추가·제외하는 관리 기능은 포함하지 않습니다.

### 8. C4 안전운전 정보 안내·신호·TBT 연동

- 티맵과 네이버지도에서 위치·속도·도로 제한속도·카메라·방지턱·구간단속·TBT(회전/분기 안내)·제공되는 차선/신호 정보를 기존 C4 호환 JSON 형식으로 전송합니다.
- 안심주행/안전운전과 경로 안내에서 엔진이 실제로 생성한 정보를 사용합니다. 지도에 그려진 정적 아이콘이나 실내 미리보기만으로 실시간 안전정보가 생성되는 것은 아닙니다.
- 네이버의 어린이보호구역 등 다른 표지판 때문에 카메라·방지턱 전송이 빠지던 문제를 보완했습니다. 잘못된 좌표가 있는 항목도 개별 처리합니다.
- 카메라와 방지턱이 함께 있으면 기본·보조 안전정보 슬롯으로 함께 전달해 수신 측에서 선택할 수 있게 했습니다.
- 구간단속 접근·구간 내부·종료 상태를 구분하고, 활성 구간의 제한속도·남은 거리를 전달하도록 보완했습니다. 구간 정보가 끝나면 상태를 초기화합니다.
- 두 앱이 함께 실행될 때 실행 식별자·순번·전후면 상태·활성 상태를 전송해 앱 전환과 오래된 데이터 판별을 지원합니다.

**전달하는 안내 정보**

| 구분 | 내용 |
|---|---|
| 안전운전 | 카메라/방지턱 종류, 남은 거리, 제한속도, 기본·보조 안전정보 |
| 구간단속 | 시작·구간 내부·종료 상태, 구간 제한속도와 남은 구간 거리 |
| 신호 | 제공되는 직진·좌회전·우회전·유턴 등 방향별 신호 상태·잔여 시간·신호 위치/거리 |
| TBT | 현재 안내와 다음 안내의 회전·분기 종류 및 각각의 남은 거리 |
| 도로·차선 | 제공되는 현재 도로 제한속도·도로명·경로/차선 정보 |

TBT는 선택한 앱의 실제 안내 경로를 따릅니다. 앱이 바뀌면 이전 앱의 신호·안전정보·TBT를 새 앱 데이터와 섞지 않도록 소스를 구분합니다. 신호의 제공 범위와 유효 시간은 원본 앱/서버 데이터를 따릅니다.

- **C4에서 가까운 카메라/방지턱을 표시하거나 감속하는 최종 판단은 C4 수신·선택·제어 코드가 담당합니다.** 앱 APK만으로 C4 동작을 모두 바꾸지는 않습니다.

폰과 C4/PC 수신기를 같은 네트워크에 연결합니다. 기본 안내 수신은 TCP 7712, 기존 검색은 UDP 7705이며, 앱별 전용 검색은 네이버 UDP 17705·티맵 UDP 17706을 사용합니다. 두 앱을 전환해서 쓰려면 C4에도 다중 앱 수신·선택을 지원하는 코드가 필요합니다. **이 저장소에는 C4 코드나 PC 로그뷰어 실행 파일을 포함하지 않습니다.**

### 9. 신호등 상태·잔여 시간과 티맵 모의주행

- 티맵 실주행/안심주행에서 받은 신호 정보를 바탕으로 `sinf`·`ssinf` 로그의 잔여 시간과 거리를 약 1초마다 갱신합니다.
- 이 반복 로그는 마지막 원본을 기준으로 한 로컬 갱신입니다. **서버가 매초 새 신호를 보내는 것과는 다릅니다.** 색상은 실제 원본 상태를 따르고 임의로 순환시키지 않습니다.
- 지나간 신호, 위치가 오래된 신호, 유효 시간이 만료된 상태를 비우도록 했습니다. GPS로 보정한 거리는 직선 거리라 도로를 따른 거리와 다를 수 있습니다.
- 티맵 모의주행에서 지원되는 전방 링크의 신호 조회·로그 전송과 신호 패널의 상태·잔여 시간 표시를 연결했습니다.
- 모의주행에서는 같은 교차로의 진행 방향 신호가 명확한 빨강일 때 가상 위치를 유지하고, 초록 신호를 받으면 진행을 재개하도록 보완했습니다. 좌회전·우회전·유턴은 해당 방향 신호가 제공될 때 구분합니다.
- 이 정지 기능은 **티맵의 가상 모의주행에 한정**되며 실제 차량 제어를 수행하지 않습니다. 정확한 정지선 정렬이나 모든 교차로 지원을 의미하지 않습니다.
- 네이버 신호도 원본이 제공하는 방향별 상태·유효 시각·잔여 시간을 사용합니다. 모순되거나 만료된 상태를 유효한 신호로 계속 내보내지 않게 했습니다.

### 10. 네이버 단속카메라 안내 설정

- 경고음 기준에 **10% 초과**를 추가했습니다. 기존 즉시·3km/h 초과·5km/h 초과 옵션도 유지합니다.
- “10% 초과”는 정확히 10%에 도달했을 때가 아니라 **10%를 넘었을 때**입니다. 예를 들어 제한 50km/h에서는 55km/h 초과, 제한 100km/h에서는 110km/h 초과가 기준입니다.
- 일반 카메라의 현재속도와 구간단속 평균속도 경고 판정에 적용합니다.
- 어린이보호구역도 선택한 경고 기준을 따르도록 수정하고, 즉시 경고로 고정된다는 기존 설명을 제거했습니다.
- 속도별 안내 시작 기준에서 **80km/h 이상 구간의 근거리 안내를 500m 전 → 600m 전**으로 바꿨습니다. 다른 속도대와 장거리 옵션은 유지합니다.
- 이 설정은 네이버 경고음 기준이며 C4의 감속 기준과는 별개입니다.

### 11. 백그라운드 동작 감시와 진단 로그

- 네이버 안내 중 백그라운드 티맵의 연결·메인 처리·안내 갱신이 멈추는 상황을 별도로 감시합니다.
- 이상이 감지되면 표시 배너·토스트·권한이 허용된 Android 알림으로 알리고, 정상 종료·회복 시 경고를 정리합니다.
- 앱의 연결과 안내 갱신 상태를 감시하며, 티맵을 자동 재실행하는 기능은 포함하지 않습니다.
- 경로 조회·추천 선택·자동 목적지 제안/취소·주행 세션·업로드 요청의 진단 로그를 보완했습니다.
- 네이버에는 급감속 등 이상 기록 분석을 위한 기존 위치·속도와 위치 갱신 상태를 기록하는 진단을 추가했습니다.
- 대표적인 앱 내부 로그 폴더는 티맵 `naver_route`, 네이버 `speed_trace`·`tmap_record_watch`·`tmap_bump_merge`입니다. 수집·분석 도구는 별도 작업 환경에서 사용합니다.

## 사용 전 확인

1. 두 앱의 수정 APK를 설치하고 위치 권한 및 백그라운드 실행에 필요한 설정을 확인합니다.
2. 티맵의 집·회사와 각 앱의 차량/연료 설정을 확인합니다. 차량 설정을 두 앱 사이에 자동 동기화하는 기능은 없습니다.
3. 네이버 과속방지턱 안내를 켜고 필요한 카메라 경고 기준·안내 거리를 선택합니다.
4. C4 연동 시 같은 네트워크와 다중 앱 수신 코드 적용 여부를 확인합니다.
5. 네이버 안내만 수동으로 종료했을 때 백그라운드 티맵이 계속 안내 중일 수 있으므로 티맵 상태도 확인합니다.

실제 제공되는 신호·안전정보와 백그라운드 유지 여부는 지도 데이터·서비스 지원 구간·GPS·네트워크·기기 설정에 영향을 받습니다.

## ARM64 패키징과 배포

- 원래 수정 APK에서 `armeabi-v7a` 라이브러리만 제거했습니다. `arm64-v8a` 라이브러리, DEX 코드, 지도·음성·화면 리소스와 AndroidManifest 내용은 해당 수정본과 동일합니다.
- 기존 Android Debug 인증서로 재서명하고, 서명과 네이티브 라이브러리의 16KB 정렬을 검증했습니다.
- ARM64 기기 전용이며, 32비트 ARM 전용 기기에는 설치할 수 없습니다.
- APK 원본은 저장소에 중복 커밋하지 않으며 복원 결과인 `dist`도 Git에서 제외합니다.
- 파일별 SHA256, APK 패키지 정보와 서명 인증서 SHA256은 `manifest.json`에 있습니다.

향후 앱을 자주 갱신하면 바이너리 변경 이력이 저장소에 계속 쌓입니다. 그때는 APK를 GitHub Releases로 배포하고 저장소에는 버전 정보만 두는 방식이 적합합니다. Releases는 파일당 2GiB 미만을 지원합니다.
